Technical Overview

Architecture, data flows, security layers and the AI pipeline behind a wellness-leaning conversation-understanding app for the Indian market.

For: Product / Eng leadership Phase 1 · Validation Updated 27 Jun 2026 Confidential
Executive snapshot

What Samvaad is, technically

A static web client talks to a single Node/Express proxy that holds all provider secrets and brokers every external call. The browser never touches a provider key. Three AI services — speech-to-text, an LLM analysis brain, and text-to-speech — are composed into one flow: understand a conversation → surface what to try → replay a kinder version. State, auth and storage are Supabase (Postgres) with row-level security and Mumbai data residency.

Client

Vanilla HTML/CSS/JS. No framework, no build step. Glassmorphism UI, inline-SVG voiced avatars.

Proxy

Express. Verifies the Supabase JWT, injects secrets from env, calls Deepgram / LLM / ElevenLabs, persists per-user rows.

Data

Supabase Postgres + Auth + Storage. RLS locks every row to its owner. Region ap-south-1 (Mumbai).
The experience

Product flow, screen by screen

The app shell is a mobile-first column with a bottom tab bar (a left rail on desktop): Home · Insights · Talk · You.

Authenticate
Magic-link or 6-digit OTP via Supabase GoTrue. A guest path exists (no persistence). Session is carried into the app.
Choose intent & bring the conversation in
Three intents — Us two (couple, consent required), A relationship (solo), Just me (introspection). Input by paste, in-browser record, or audio upload.
Analyse
A report is produced: scores (connection, empathy, escalation risk, overall), the patterns underneath, what each person did well, and exact "scripts" to try next time. Content is fully dynamic — healthy exchanges are not padded with invented faults.
Intervene
A guided walk-through (slideshow) paces it: strengths first, a contextual 60-second breathing reset only when escalation is high, scripts, then a voiced animated kinder replay of the same moment, softened.
Stay connected
Optional WhatsApp daily check-in opt-in (own number only). Sessions accrue on Home (recent reflections) and Insights (trend over time).

Data flow

A request, end to end

Sign-in Supabase /auth/v1
GoTrue issues a JWT (magic-link hash or OTP verify). Held in sessionStorage; every backend call sends it as a Bearer token.
Transcribe audio POST /api/transcribe
Audio is base64'd to the proxy → Deepgram nova-2 with diarize=true → speaker-separated transcript returned. Raw audio is auto-deleted after transcription (purpose limitation).
Analyse POST /api/analyze
Two-step LLM call to avoid truncation: (1) report JSON — scores, summary, speaker genders, patterns, strengths, improvements, KPIs; (2) improved-conversation JSON — a kinder rewrite with per-turn speaker + emotion for the replay. Persisted to sessions under the caller's user_id (RLS).
Voice the replay POST /api/tts
Each rewritten line → ElevenLabs eleven_multilingual_v2 → audio streamed back; the inline-SVG avatar lip-syncs and emotes per line.
Feedback & history /api/feedback · /api/history
A one-tap "will you try this?" signal is logged (the seed for a future contextual-bandit recommender). History rehydrates the dashboard.
Daily-loop opt-in POST /api/optin
Stores the user's own WhatsApp number to nudge_subscriptions (stub — no provider wired yet). Consent-based, honors STOP.
Security & privacy

Defense in depth, basic → advanced

1
Transport. HTTPS everywhere; secrets never traverse the client.
2
Secret isolation. Every provider key (Deepgram, LLM, ElevenLabs, Supabase service_role) lives only in the proxy's environment. The browser ships solely the publishable Supabase key, which is public by design.
3
Authentication. Supabase GoTrue (magic-link + OTP). The proxy verifies the JWT via getUser before any privileged operation.
4
Authorization. Postgres Row-Level Security on every table; policies enforce auth.uid() = user_id — a user can read/write only their own rows.
5
Data minimization. Raw audio is deleted right after transcription. Consent for couple recordings is logged to a dedicated consents table.
6
Key scoping & caps. The ElevenLabs key is scoped to Text-to-Speech only, with a monthly character cap — blast-radius and cost are bounded.
7
Two-party & own-number rules. Couple analysis requires an explicit consent checkbox; WhatsApp opt-in accepts the user's own number only — no third-party PII captured by default.
8
Residency. All data sits in ap-south-1 (Mumbai) for India DPDP data-residency expectations.

Data model

Tables & ownership

All tables carry user_id and are RLS-locked to the authenticated owner. Schema is mirrored in backend/schema.sql.

sessions

One row per analysis: mode/submode, names, scores, summary, patterns, strengths, improvements, the improved (replay) turns, KPIs.

feedback

The "will you try this?" signal with context (escalation risk, mode) — training data for a future {context → intervention → outcome} recommender.

consents

An auditable consent record tied to a session (e.g. both-partners vs self-only).

nudge_subscriptions

WhatsApp daily check-in opt-ins (own number, opt-out honored). Provider not yet wired.

AI pipeline

From audio to a kinder replay

STT + diarization
Audio → speaker-labelled transcript. Paste/record paths skip this step.
Report generation (LLM call 1)
A Gottman-method-informed prompt returns strict JSON: scores, neutral non-blaming patterns/strengths, verbatim Hinglish "scripts," KPI awareness signals, and inferred speaker gender (drives correct avatars). Instructed to return empty arrays when the exchange is genuinely healthy.
Kinder rewrite (LLM call 2)
The same conversation rewritten applying the improvements; each turn tagged with speaker (A/B, strictly alternating) and an emotion that drives facial expression.
Voiced avatar replay
Per-line TTS + a CSS-driven SVG rig (blink, lip-sync, brows, blush, head-tilt, per-emotion expression). Two speakers are distinguished by voice and avatar; gender is data-driven, not hardcoded.

Framing guardrail

Output is written as everyday wellness language, never clinical. Voice-biomarker KPIs (pitch/jitter/rate) are staged for later, not implemented.
Compliance posture

India DPDP Act 2023 + 2025 Rules

Consent-first & purpose limitation. Explicit consent for couple recordings; raw audio auto-deleted after its single purpose (transcription).
Data residency. Mumbai (ap-south-1) storage.
Per-user isolation. RLS everywhere; a user only ever sees their own rows.
Minors & sensitivity. No under-18 without parental consent; framing kept warm and everyday, never clinical.
